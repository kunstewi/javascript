## What is the difference between declaring a variable with `var`, `let`, and `const`?

### The Concept of Scoping and Variable Lifecycle

In JavaScript, variable declaration defines how a piece of data is bound to a specific identifier and how long that identifier remains accessible during the execution of a program. This lifecycle is governed by **Scope**—the "visibility" of variables—and the **Temporal Dead Zone (TDZ)**. Historically, JavaScript only had **Function Scope** via the `var` keyword. However, as applications grew more complex, the need for more granular control over memory and state led to the introduction of **Block Scope** in ES6 (2015) with `let` and `const`. The difference between these three keywords lies in three technical areas: **Scope**, **Hoisting behavior**, and **Reassignment capabilities**.

### Var: The Legacy Function Scope

The `var` keyword is the original way to declare variables. It is characterized by its permissive nature and lack of block-level restrictions.

* **Scope**: `var` is **Function-Scoped**. If declared inside a function, it is local to that function. If declared outside, it becomes a property of the global object (e.g., `window` in browsers). It ignores block boundaries like `if` statements or `for` loops.

* **Hoisting**: Variables declared with `var` are hoisted to the top of their scope and initialized with `undefined`. You can reference them before their declaration line without a crash.

* **Reassignment & Redeclaration**: You can both reassign the value and redeclare the variable name entirely within the same scope without the engine throwing an error.

### Let: The Modern Block Scope

`let` was introduced to solve the "leaky" nature of `var`. It provides a much stricter and more predictable way to manage variables.

* **Scope**: `let` is **Block-Scoped**. A "block" is any code enclosed in curly braces `{}`. This includes `if` blocks, `loops`, and even standalone `{}` blocks. The variable exists only within that specific block.
* **Hoisting & TDZ**: While `let` is technically hoisted by the engine, it is **not initialized**. It enters the **Temporal Dead Zone (TDZ)** from the start of the block until the engine reaches the declaration line. Accessing it early results in a `ReferenceError`.
* **Reassignment**: You can reassign the value (`let x = 1; x = 2;`), but you **cannot redeclare** it in the same scope.

### Const: Immutable Bindings

The `const` keyword (short for "constant") is used for values that should not be reassigned after their initial creation. It follows the same scoping and hoisting rules as `let`.

* **Assignment**: A `const` variable **must** be initialized at the time of declaration. You cannot declare it and assign a value later.
* **Immutability Quirk**: A common misconception is that `const` makes data immutable. It does not. It creates a **constant reference**.
* If a `const` holds a primitive (like a Number), the value cannot change.
* If a `const` holds a non-primitive (like an Object or Array), the **reference** to the object is fixed, but the **properties** inside that object can still be modified. To make the object itself immutable, one would need `Object.freeze()`.

### Technical Comparison Summary

| Feature | `var` | `let` | `const` |
| --- | --- | --- | --- |
| **Scope** | Function Scope | Block Scope | Block Scope |
| **Hoisting** | Yes (initialized as `undefined`) | Yes (uninitialized/TDZ) | Yes (uninitialized/TDZ) |
| **Redeclaration** | Permitted | Forbidden | Forbidden |
| **Reassignment** | Permitted | Permitted | Forbidden |
| **Global Object** | Adds to `window`/`global` | No | No |

### Internal Engine Behavior: Memory and Optimization

From the perspective of the **V8 Engine**, using `const` and `let` allows for better optimization. Because `const` guarantees a reference won't change, the engine can make certain assumptions during the **Just-In-Time (JIT) Compilation** phase. Furthermore, because block-scoped variables are cleaned up as soon as the block finishes execution, they often lead to more efficient memory management on the **Stack** compared to `var` variables that might linger for the duration of an entire function.
