## What are the primitive and non primitive data types in JavaScript?

### Data Type

At its core, a Data Type is a classification that tells the interpreter how the programmer intends to use a piece of data. This classification determines how much space the data occupies in memory and what operations can be performed on it.

In JavaScript, the distinction between Primitive and Non-Primitive types is not just semantic; it defines how the JavaScript Engine (like V8 or SpiderMonkey) allocates memory and handles variable assignment.

Primitives are stored "by value" on the Stack, while Non-Primitives are stored "by reference" on the Heap.

### Primitive Data Types

Primitive types are the lowest-level implementation of data in the language. They are immutable, meaning once a primitive value is created, it cannot be altered. While you can reassign a variable to a new primitive value, the original value itself remains unchanged in memory until it is garbage collected. Because they have a fixed size, the engine stores them in the Stack, which allows for high-speed access.

There are currently seven primitive types in JavaScript:

- Number: Represents both integer and floating-point numbers. Unlike many languages that have int, float, or double, JavaScript uses the IEEE 754 standard (64-bit binary format). This leads to the famous quirk where 0.1 + 0.2 != 3 due to precision limits. The range for safe integers is restricted to -(2^53 - 1) through 2^53 - 1 .

- String: A sequence of characters used to represent text. Strings are indexed starting at 0, but because they are primitive and immutable, methods like .toUpperCase() do not change the original string; they return a brand-new one.

- Boolean: A logical entity that can have only two values: true or false. These are vital for control flow and conditional logic.

- Undefined: A variable that has been declared but has not yet been assigned a value is automatically given the type undefined. It represents the "absence of a value."

- Null: This is an intentional "empty" value. It must be assigned explicitly. A historical quirk in JavaScript is that typeof null returns "object", which is a long-standing bug in the language's implementation that was never fixed to maintain backward compatibility.

- BigInt: Introduced in ES2020, this type allows for the representation of integers larger than the maximum limit of the Number type. It is created by appending n to an integer literal (e.g., 9007199254740991n).

- Symbol: Introduced in ES6, Symbols are unique and anonymous identifiers. Even if two symbols are created with the same description, they are strictly unequal ($Symbol('a') \neq Symbol('a')$). They are primarily used to add "hidden" properties to objects that won't collide with other keys.

### Non-Primitive (Reference) Data Types

Non-primitive types, often referred to as Reference Types, are collections of properties and are mutable. Unlike primitives, these can be quite large and have a dynamic size, so the JavaScript engine stores the actual data on the Heap (a large, unstructured region of memory) and places a reference (a memory address pointer) on the Stack.

In JavaScript, there is essentially only one non-primitive type: Object. However, many built-in structures are specialized versions of the Object:

- Object: The fundamental building block. It is a collection of key-value pairs where keys are strings (or symbols) and values can be any data type.

- Array: A specialized object used for storing ordered lists. While they look like lists in other languages, JavaScript arrays are actually objects with numeric keys and a special length property.

- Function: In JavaScript, functions are "first-class citizens." They are technically objects that have the capability of being called (executed). Because they are objects, you can even add properties and methods to a function.

- Date, RegExp, Map, Set: These are all built-in standard objects designed for specific tasks like handling time, regular expressions, or unique collections.

### Value vs Reference

The most critical technical takeaway is how these types behave during assignment. When you copy a Primitive, you create a real copy of the value. When you copy a Non-Primitive, you are only copying the reference (the pointer).

- Memory Management: Primitives are handled via a simple stack pointer, making them incredibly fast. Non-primitives require the Garbage Collector to periodically scan the Heap to see if any objects are no longer "reachable" by any reference on the Stack to free up memory.

- Comparison: Primitives are compared by value ($5 === 5$). Non-primitives are compared by reference. Two objects {a: 1} and {a: 1} are not equal because they occupy different locations in the Heap memory.
