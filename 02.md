## Explain the difference between `null` and `undefined`.


### Concept of Absence

In JavaScript, a variable's lifecycle typically begins with a declaration. If the engine reaches a point where it must evaluate a variable that has been declared but not yet "filled" with data, it needs a placeholder to maintain type safety and prevent the system from crashing. This "placeholder" is the core of the distinction: one is a default state provided by the language (undefined), while the other is a deliberate state provided by the developer (null).

### Undefined: The Lack of Initialization

undefined is a primitive value automatically assigned by the JavaScript Engine to any variable that has been declared but has not been assigned a value. It signifies that the variable exists in the Execution Context, but the memory space allocated for it on the Stack does not yet contain a meaningful data pointer or literal.

- Automatic Assignment: You will encounter undefined when accessing a variable that hasn't been initialized, a function property that doesn't exist, or a function that finishes execution without an explicit return statement.

- Type Identity: The type of undefined is, appropriately, "undefined".

- Global Object: Historically, undefined is a property of the global object (e.g., window.undefined in browsers). In older versions of JavaScript (pre-ES5), it was actually possible to reassign the value of the global undefined, which led to catastrophic bugs. Modern engines have since made it a non-configurable, non-writable property.

- Engine Behavior: During the Creation Phase of an execution context, the engine performs "Hoisting." It sets aside memory for variables declared with var and initializes them to undefined before a single line of code is actually run.

### Null: The Intentional Absence

null is a primitive value that represents the intentional absence of any object value. It is never set by the JavaScript engine; it must be assigned by the programmer to indicate that a variable is "empty" or that an expected object is missing.

- Manual Assignment: It is commonly used as a placeholder in APIs or data structures where an object is expected but currently unavailable. For example, a search function might return null if no user is found in a database.

- The Type Quirk: As noted previously, executing typeof null returns "object". This is not because null is a non-primitive; it is a legacy bug from the first version of JavaScript. In the original implementation, values were stored in 32-bit units, with a "type tag" in the first few bits. The tag for objects was 000. Because null was represented as the null pointer (all zeros), the engine incorrectly identified it as an object.

- Memory Management: Assigning null to a variable that previously held a large object is a common pattern to signal to the Garbage Collector that the object is no longer needed, allowing the memory on the Heap to be reclaimed.
