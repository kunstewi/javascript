## What is `NaN`? What is its type?

### The Concept of Computational Failure

In computer science, when a mathematical operation is performed that cannot result in a meaningful or representable number, the system needs a way to signal this failure without crashing the entire program. **`NaN`**, which stands for **"Not-a-Number"**, is a special symbolic value defined by the **IEEE 754** floating-point standard. It acts as a sentinel value, indicating that an arithmetic operation has returned an undefined or unrepresentable result (such as dividing zero by zero or attempting to calculate the square root of a negative number).

### The Technical Nature and Type of NaN

Despite its name literally being "Not-a-Number," the **JavaScript Engine** classifies `NaN` as a numeric type. When you query the engine using the `typeof` operator, the result is:

```javascript
typeof NaN; // "number"

```

This often confuses developers, but it is logically consistent with the IEEE 754 standard. `NaN` is a valid state of a 64-bit float, just like `Infinity` or `-0`. Internally, the engine treats it as a member of the **Number** data type so that mathematical functions can return a value that remains within the same type domain, preventing type errors during complex calculations.

### How NaN is Generated

The engine produces `NaN` whenever a mathematical transformation fails to yield a real number. Common scenarios include:

* **Failed String Parsing**: Attempting to convert a non-numeric string into a number.
* `Number("Hello")` or `parseInt("ABC")`


* **Indeterminate Forms**: Mathematical operations that have no defined limit.
* `0 / 0`, `Infinity / Infinity`, or `Infinity - Infinity`


* **Invalid Math Functions**: Operations outside the domain of real numbers.
* `Math.sqrt(-1)` or `Math.log(-1)`


* **Operand Coercion Failure**: Using `NaN` in any further calculation.
* `5 + NaN` results in `NaN`. This is known as **NaN Propagation**—once a calculation is "polluted" by a `NaN`, the entire chain usually results in `NaN`.

### The Identity Crisis: Comparison and Equality

The most significant "quirk" of `NaN` is its behavior during comparison. According to the specification, **`NaN` is the only value in JavaScript that is not equal to itself.**

* `NaN == NaN` is `false`.
* `NaN === NaN` is `false`.

This design exists because two different failed operations (e.g., `0/0` and `Math.sqrt(-1)`) are both represented as `NaN`, but they do not represent the "same" mathematical failure.


### Detecting NaN Correctly

Because `NaN` cannot be checked using standard equality operators, JavaScript provides specific methods to identify it:

1. **`isNaN()` (Global)**: This function is often avoided because it forces **Type Coercion**. It returns `true` for anything that *becomes* `NaN` when converted to a number. For example, `isNaN("hello")` is `true`, even though the string "hello" is not the value `NaN`.

2. **`Number.isNaN()` (ES6)**: This is the robust, preferred method. it does **not** perform coercion. It only returns `true` if the value is currently `NaN` and its type is `Number`.

3. **Self-Comparison**: Because `NaN` is the only value not equal to itself, a common "hack" is `x !== x`. If this evaluates to `true`, then `x` is `NaN`.

4. **`Object.is()`**: This method behaves like `===` but handles edge cases. `Object.is(NaN, NaN)` evaluates to `true`.
