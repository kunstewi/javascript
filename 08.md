## Are variables declared with `const` immutable? Explain.

### The Concept of Constant Bindings

In the context of programming languages, **Immutability** refers to the inability of a data value to be altered after its creation. However, in JavaScript, the `const` keyword does not signify that the *value* is immutable, but rather that the **binding** (the connection between the variable name and the memory address) is immutable. When you declare a variable with `const`, you are telling the **JavaScript Engine** that the identifier cannot be reassigned to a different memory address. Whether the data itself can change depends entirely on whether that data is a **Primitive** or a **Non-Primitive (Reference)** type.

---

### Primitive Types and Const

When a `const` variable holds a **Primitive** type (such as a Number, String, or Boolean), it effectively becomes immutable. This is because primitives are stored by value directly on the **Stack**. Since the value is stored at the location the variable points to, and `const` prevents the variable from pointing elsewhere or changing that specific value, the data cannot be modified.

```javascript
const score = 10;
score = 20; // TypeError: Assignment to constant variable.

```

In this case, the engine prevents the reassignment, and since there are no methods to "mutate" a number in place, the value `10` is functionally immutable.

---

### Non-Primitive Types and Mutation

The behavior changes significantly when `const` is used with **Objects** or **Arrays**. These are **Reference Types**, meaning the variable stored on the Stack doesn't hold the data itself, but rather a **Pointer** (memory address) to a location on the **Heap** where the actual object resides.

`const` only protects the **Pointer** on the Stack. It does not protect the data inside the Heap.

* **Fixed Reference**: you cannot point the variable to a completely new object or array.
* **Mutable Content**: You can freely add, remove, or modify properties within that object or elements within that array.

```javascript
const user = { name: "Gemini" };

// This is ALLOWED: Mutating the object properties
user.name = "Flash"; 
user.age = 3;

// This is FORBIDDEN: Reassigning the reference
user = { name: "New Model" }; // TypeError

```

---

### Achieving True Immutability: `Object.freeze()`

If your goal is to make the data itself immutable (so that properties cannot be changed), you must use the `Object.freeze()` method. This is a shallow operation that prevents the addition, deletion, or modification of existing properties on an object.

* **Shallow Freeze**: `Object.freeze()` only affects the immediate properties of the object. If the object contains nested objects, those nested objects are still mutable unless they are also frozen.
* **Strict Mode**: In "strict mode," attempting to change a frozen object will throw an error; in non-strict mode, it will simply fail silently.

### Technical Comparison: Const vs. Freeze

| Feature | `const` | `Object.freeze()` |
| --- | --- | --- |
| **Level** | Variable Binding (Stack) | Object Value (Heap) |
| **Reassignment** | Forbidden | Permitted (if declared with `let`) |
| **Mutation** | Permitted (for objects/arrays) | Forbidden |
| **Mechanism** | Language Syntax | Standard Library Method |

### Internal Engine Behavior: Memory Optimization

From an internal perspective, the **V8 Engine** benefits from `const` declarations. When the engine's **Just-In-Time (JIT) Compiler** sees a `const` binding, it can perform **Inline Caching** more effectively because it knows the reference will never point to a different object structure. However, it still must account for potential mutations of the object's properties unless it can prove through "escape analysis" that the object is never changed.
