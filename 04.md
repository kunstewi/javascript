## How does type coercion work in JavaScript? Give examples.

### Type Coercion

Type Coercion is the automatic or implicit conversion of values from one data type to another (e.g., strings to numbers). Unlike Type Casting, which is an explicit action taken by the programmer (such as using Number(value)), coercion is performed by the JavaScript Engine at runtime to satisfy the requirements of an operator or a functional context. This mechanism is a byproduct of JavaScript being a Weakly Typed language. The engine uses internal abstract operations—primarily ToPrimitive, ToNumber, and ToString—to resolve conflicts between mismatched types during execution.

### Internal Mechanish

When the engine encounters an operation involving a non-primitive (like an object or array) and a primitive, it must first convert the object into a primitive value. This is handled by the internal ToPrimitive algorithm, which follows a specific hierarchy:

- Symbol.toPrimitive: If the object has a method defined by this symbol, it is called first.

- valueOf(): If the first step isn't applicable, the engine calls valueOf(). For most objects, this simply returns the object itself.

- toString(): If valueOf() does not return a primitive, the engine calls toString().

### Numeric Coercion

- Addition (+): This operator is overloaded. It performs both mathematical addition and String Concatenation. If either operand is a string, the engine coerces the other operand to a string and joins them.

Example: 5 + "5" = "55" Example: 1 + 2 + "3" = "33" (Evaluated left-to-right: $1+2=3$, then $3+"3"$)

- Subtraction, Multiplication, Division: These operators do not have a string counterpart. Therefore, the engine always attempts to coerce both operands into Numbers.

Example: "10" - 2 = 8 Example: "10" * "2" = 20 Example: "10" - "five" = NaN (The string "five" cannot be converted to a valid number).

### Boolean

In logical contexts (like if statements or ternary operators), JavaScript coerces values into booleans. This is referred to as Boolean Coercion. Every value in JavaScript is inherently "Truthy" unless it is defined as one of the following eight "Falsy" values:

- false

- 0 (and -0, 0n)

- "" (Empty string)

- null

- undefined

- NaN

- document.all (A historical quirk for browser compatibility)

Anything not on this list—including empty arrays [] and empty objects {}—coerces to true. This is why a common bug involves checking if (myArray) to see if an array has items; an empty array is truthy, so the check will pass even if the array is empty.


### Specific Examples

To visualize the engine's internal logic, consider these "quirky" but logically consistent results:

- true + 1 = 2: The boolean true is coerced to the number 1.

- !! "hello" = true: The double-bang operator is a common pattern to explicitly coerce a value to a boolean. The first ! coerces it to false (the inverse of its truthy state), and the second ! flips it back to true.

- [] + [] = "": When two arrays are added, they are both coerced to primitives. Since valueOf() for an array returns the array itself, the engine calls toString(). An empty array's string representation is "". Thus, "" + "" equals "".

- [] + {} = "[object Object]": The array becomes "" and the object becomes "[object Object]".
