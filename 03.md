## What is the difference between `==` and `===`?

### Abstract Equality Operator (==)

The Abstract Equality Operator, often called "loose equality," compares two values for equality after performing any necessary type conversions. This behavior is governed by a complex set of rules in the ECMAScript specification known as the Abstract Equality Comparison Algorithm.

- Coercion Logic: If the two operands are of different types, the engine attempts to convert them to a "neutral" type (usually a Number) to see if they represent the same underlying data.

- Common Use Cases: It is frequently used when a developer wants to check if a value is "nullish" (either null or undefined) without writing two separate checks, as null == undefined evaluates to true.

- The "Quirks" of Coercion: Because the engine follows a specific priority for conversion, it can lead to results that feel counter-intuitive. For example, [] == false is true. This happens because the empty array is coerced to an empty string "", which is then coerced to the number 0, and the boolean false is also coerced to 0.

### Strict Equality Operator (===)

The Strict Equality Operator, often called "identity" or "triple-equals," compares both the Value and the Data Type of the operands. It does not perform type coercion. If the types are different, the expression immediately returns false.

- Comparison Logic: For the expression to be true, both sides must point to the same value in memory (for primitives) or the same reference (for objects), and they must share the same type.

- Predictability: Because it bypasses the coercion algorithm, === is much faster and less prone to bugs. It ensures that the developer is comparing exactly what they intend to compare.

- Handling NaN: A unique quirk of the strict equality operator is its treatment of NaN (Not-a-Number). According to the IEEE 754 standard, NaN === NaN is false. To check for NaN, one must use Number.isNaN() or Object.is().
